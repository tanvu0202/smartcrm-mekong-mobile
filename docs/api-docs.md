# API Documentation — Smart CRM (Mekong Mobile), flow L4, tag v1.0

REST API of the warranty-ticket system: a manager assigns technicians to tickets and books hand-over (`GIAO`) / pick-up (`NHAN`) appointments; a technician sees and updates only his own tickets.
The Vietnamese contract used during development is [api-contract.md](api-contract.md). Real request/response pairs, copied from a live run of every endpoint, are in [api-examples.md](api-examples.md) (generated by `scripts/lay-vi-du-api.js`).

## 1. Conventions

| Item | Rule |
|---|---|
| Base URL | `http://localhost:3000/api` (the port is `APP_PORT`, see the [Deployment Guide](deployment-guide.md)) |
| Format | JSON, UTF-8. Send `Content-Type: application/json` with a body. Body size limit: 100 kB (Express default). |
| Authentication | `Authorization: Bearer <token>` on every endpoint except `GET /health` and `POST /auth/login`. The token comes from `POST /auth/login`, is signed with `AUTH_SECRET` (HS256) and lives 8 hours by default. |
| Field names | Request bodies use camelCase (`customerName`, `startTime`). Responses keep database names in snake_case (`ticket_id`, `due_date`). |
| Identifiers | Numbers, except `log_id` which is a string (bigint). |
| Date-times | ISO 8601 strings in UTC, for example `2027-02-26T02:00:00.000Z`. Impossible dates (30 Feb) are rejected, not shifted. |
| Lists | Returned as `{ "data": [ ... ] }`. A single object is `{ "data": { ... } }`, except assign / reassign / status which return `{ "ticket", "log" }`. |
| Errors | Always `{ "error": { "code": "...", "message": "...", "details": [ ... ] } }` (`details` only for validation errors). Messages are in Vietnamese and never contain stack traces, table names or connection strings. |

### Roles

| Role | Allowed |
|---|---|
| `QUAN_LY` (manager, demo account `dieu.phoi`) | every endpoint |
| `KTV` (technician, demo accounts `ktv.hai`, `ktv.long`) | `GET /tickets` (the server returns only his own tickets), `GET /tickets/{id}` and `POST /tickets/{id}/status` (only his own tickets, otherwise 403), `/auth/*`, `/health` |

Demo password: `DEMO_PASSWORD` (default `demo123`, public by design, see the security checklist).

### Enumerations

| Name | Values |
|---|---|
| Ticket `status` | `MOI` (new) → `DA_PHAN_CONG` (assigned) → `DANG_XU_LY` (in progress) → `HOAN_TAT` (done) |
| `priority` | `1` high, `2` medium, `3` low |
| `issue_group` | `MAN_HINH`, `PIN`, `SAC`, `LOA`, `CAMERA`, `PHAN_MEM`, `KHAC` |
| Appointment `type` | `GIAO` (hand over to the customer), `NHAN` (receive from the customer) |
| Appointment `status` | `DA_DAT` (booked), `DA_HUY` (cancelled) |
| `ticket_log.action` | `PHAN_CONG` (first assignment), `DOI_KTV` (reassignment), `DOI_TRANG_THAI` (status change) |

### Business rules the API enforces

| Rule | Meaning |
|---|---|
| QT-01 | Status moves forward one step at a time; a done ticket is closed. |
| QT-02 | A ticket is assigned once (`assign`); afterwards only `reassign`. Two managers assigning at the same moment: the second gets 409. |
| QT-03 | Only technicians of the ticket's service center with proficiency ≥ 3 are suggested; assigning another center's technician is rejected (422). |
| QT-04 | `reassign` needs a `reason`; for a ticket in `DANG_XU_LY` it also needs `confirm: true`. |
| QT-05 | A technician cannot have two booked appointments that overlap in time (touching end points are allowed). |
| QT-06 | A technician with 10 or more open tickets is flagged `overloaded`; the API only warns. |

Status changes and their `ticket_log` row are written in one transaction, and the ticket row is locked (`SELECT … FOR UPDATE`), so concurrent requests queue up.

## 2. Error codes

| HTTP | `code` | When |
|---|---|---|
| 400 | `VALIDATION_ERROR` | Missing or malformed field, invalid JSON, wrong type of an id, text too long (customer name and device model ≤ 100, reason ≤ 255 characters), blank text, bad phone (`+` only at the start, then 8–15 digits), impossible date. `details` lists the wrong fields. |
| 401 | `UNAUTHENTICATED` | No `Authorization` header, wrong format, or a token that was altered. |
| 401 | `TOKEN_EXPIRED` | The token is older than its lifetime; sign in again. |
| 401 | `INVALID_CREDENTIALS` | Wrong user name or password (the same answer for both). |
| 401 | `ACCOUNT_DISABLED` | The account exists but is switched off. |
| 403 | `FORBIDDEN` | Wrong role, or a technician touching a ticket that is not his. |
| 404 | `NOT_FOUND` | Ticket or appointment does not exist. |
| 409 | `TICKET_NOT_EDITABLE` / `TICKET_NOT_DELETABLE` | Edit or delete of a ticket that is no longer `MOI`. |
| 409 | `TICKET_ALREADY_ASSIGNED` | `assign` on a ticket that is not `MOI` (includes losing a race with another manager). |
| 409 | `TICKET_NOT_ASSIGNED` | `reassign` or booking an appointment on a ticket that has no technician. |
| 409 | `ALREADY_ASSIGNED` | Reassigning to the technician who already holds the ticket. |
| 409 | `CONFIRM_REQUIRED` | `reassign` of a `DANG_XU_LY` ticket without `confirm: true`. |
| 409 | `TICKET_CLOSED` | Reassigning or booking on a `HOAN_TAT` ticket. |
| 409 | `STATUS_SKIP` | Jumping a step (`DA_PHAN_CONG` → `HOAN_TAT`). |
| 409 | `INVALID_TRANSITION` | Going backwards or repeating the current status. |
| 409 | `APPOINTMENT_OVERLAP` | The technician already has a booked appointment in that time; also returned by `reassign` when the new technician's calendar clashes with the ticket's appointments. |
| 409 | `APPOINTMENT_CANCELLED` | Editing or cancelling an appointment that is already cancelled. |
| 422 | `TECH_OTHER_CENTER` / `TECH_INVALID` | Technician belongs to another center, does not exist, or is inactive. |
| 422 | `DB_CONSTRAINT` | A database constraint was violated (foreign key, check, unique). |
| 500 | `INTERNAL` | Unexpected error; the message is the generic "Lỗi hệ thống". |
| 503 | `DB_UNAVAILABLE` | The database cannot be reached (the API gives up after 5 seconds, `DB_CONNECT_TIMEOUT_MS`). |

## 4. Endpoint reference

The ticket object used below:

```json
{
  "ticket_id": 19, "ticket_code": "BH-0019", "center_id": 1, "technician_id": null,
  "customer_name": "API Example Customer", "customer_phone": "0912345678",
  "device_model": "iPhone 13", "issue_group": "MAN_HINH", "issue_description": "Cracked screen",
  "priority": 1, "status": "MOI",
  "due_date": "2028-04-01T10:00:00.000Z", "created_at": "2026-11-12T15:34:17.851Z"
}
```

The appointment object: `{ "appointment_id": 9, "ticket_id": 19, "appointment_type": "GIAO", "start_time": "…", "end_time": "…", "status": "DA_DAT", "created_at": "…" }` (the list endpoint returns only `appointment_id`, `appointment_type`, `start_time`, `end_time`).

The log object: `{ "log_id": "22", "ticket_id": 19, "action": "PHAN_CONG", "old_technician_id": null, "new_technician_id": 3, "old_status": "MOI", "new_status": "DA_PHAN_CONG", "reason": null, "changed_by": "dieu.phoi", "changed_at": "…" }`. `changed_by` comes from the token, never from the request body.

### 1. GET /health

- **Purpose:** tells Docker and the operator whether the server and the database are up.
- **Access:** public.
- **Request:** none.
- **Success 200:** `{ "status": "ok", "db": "up" }`.
- **Errors:** 503 `{ "status": "degraded", "db": "down" }` when the database does not answer.
- **Example:** `curl http://localhost:3000/api/health`

### 2. POST /auth/login

- **Purpose:** exchange a user name and password for a token.
- **Access:** public.
- **Request body:** `{ "username": "dieu.phoi", "password": "demo123" }` (both required).
- **Success 200:** `{ "token": "<token>", "expiresIn": 28800, "user": { "username", "fullName", "role", "technicianId" } }`. `technicianId` is `null` for the manager.
- **Errors:** 400 `VALIDATION_ERROR` (missing field or broken JSON); 401 `INVALID_CREDENTIALS`; 401 `ACCOUNT_DISABLED`.
- **Example:** `curl -X POST http://localhost:3000/api/auth/login -H "Content-Type: application/json" -d '{"username":"dieu.phoi","password":"demo123"}'`

### 3. GET /auth/me

- **Purpose:** the user behind the token (the web UI calls it at start-up).
- **Access:** any signed-in user.
- **Request:** header `Authorization: Bearer <token>`.
- **Success 200:** `{ "user": { "username", "role", "technicianId", "fullName" } }`.
- **Errors:** 401 `UNAUTHENTICATED`, 401 `TOKEN_EXPIRED`.
- **Example:** `curl http://localhost:3000/api/auth/me -H "Authorization: Bearer $TOKEN"`

### 4. GET /centers

- **Purpose:** service centers, for the filter of the ticket queue.
- **Access:** manager.
- **Request:** none.
- **Success 200:** `{ "data": [ { "center_id": 1, "name": "Trung tâm Quận 1", "address": "…", "phone": "…" }, … ] }` (2 centers in the sample data).
- **Errors:** 401; 403 `FORBIDDEN` for a technician.
- **Example:** `curl http://localhost:3000/api/centers -H "Authorization: Bearer $TOKEN"`

### 5. GET /technicians

- **Purpose:** active technicians, for choosing one by hand.
- **Access:** manager.
- **Request query:** `center_id` (optional integer).
- **Success 200:** `{ "data": [ { "technician_id": 3, "center_id": 1, "full_name": "Lê Phúc", "phone": "0901000001", "is_active": true }, … ] }`.
- **Errors:** 401; 403.
- **Example:** `curl "http://localhost:3000/api/technicians?center_id=1" -H "Authorization: Bearer $TOKEN"`

### 6. GET /tickets

- **Purpose:** the ticket queue, sorted by priority and due date. A technician receives only his own tickets, whatever filters he sends.
- **Access:** manager, technician.
- **Request query (all optional):** `status` (one of the four statuses), `center_id`, `technician_id`.
- **Success 200:** `{ "data": [ <ticket> + "appointment_start" ] }`. `appointment_start` is the earliest booked appointment of the ticket, or `null`.
- **Errors:** 401.
- **Example:** `curl "http://localhost:3000/api/tickets?status=MOI&center_id=1" -H "Authorization: Bearer $TOKEN"`

### 7. POST /tickets

- **Purpose:** create a ticket (used to enter test data); it starts as `MOI`.
- **Access:** manager.
- **Request body:** `centerId`, `customerName` (≤ 100), `customerPhone`, `deviceModel` (≤ 100), `issueGroup`, `priority`, `dueDate` are required; `issueDescription` is optional.
  ```json
  { "centerId": 1, "customerName": "Nguyễn Văn A", "customerPhone": "0912345678",
    "deviceModel": "iPhone 13", "issueGroup": "MAN_HINH", "priority": 1,
    "issueDescription": "Cracked screen", "dueDate": "2028-04-01T10:00:00Z" }
  ```
- **Success 201:** `{ "data": <ticket> }` with a new `ticket_code` (`BH-0019`).
- **Errors:** 400 `VALIDATION_ERROR` with `details`, for example `["customerPhone không hợp lệ"]`; 401; 403.
- **Example:** `curl -X POST http://localhost:3000/api/tickets -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"centerId":1,"customerName":"A","customerPhone":"0912345678","deviceModel":"iPhone 13","issueGroup":"MAN_HINH","priority":1,"dueDate":"2028-04-01T10:00:00Z"}'`

### 8. GET /tickets/{id}

- **Purpose:** one ticket.
- **Access:** manager; a technician only for his own ticket.
- **Request:** path `id` (integer).
- **Success 200:** `{ "data": <ticket> }`.
- **Errors:** 400 (id is not a number); 401; 403 (not his ticket); 404 `NOT_FOUND`.
- **Example:** `curl http://localhost:3000/api/tickets/19 -H "Authorization: Bearer $TOKEN"`

### 9. PUT /tickets/{id}

- **Purpose:** correct the customer and device data of a ticket that nobody has taken yet.
- **Access:** manager.
- **Request body:** same fields as `POST /tickets` except `centerId`.
- **Success 200:** `{ "data": <ticket> }`.
- **Errors:** 400; 401; 403; 404; 409 `TICKET_NOT_EDITABLE` (status is not `MOI`).
- **Example:** `curl -X PUT http://localhost:3000/api/tickets/19 -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{ … same fields … }'`

### 10. DELETE /tickets/{id}

- **Purpose:** remove a ticket created by mistake.
- **Access:** manager.
- **Request:** path `id`.
- **Success 204:** empty body.
- **Errors:** 401; 403; 404; 409 `TICKET_NOT_DELETABLE` (status is not `MOI`).
- **Example:** `curl -X DELETE http://localhost:3000/api/tickets/20 -H "Authorization: Bearer $TOKEN"`

### 11. GET /tickets/{id}/suggestions

- **Purpose:** technicians who may take the ticket: same center, proficiency ≥ 3, best first (QT-03), with their current load (QT-06).
- **Access:** manager.
- **Request:** path `id`.
- **Success 200:** `{ "data": [ { "technician_id": 3, "full_name": "Lê Phúc", "phone": "0901000001", "proficiency": 5, "open_tickets": 0, "overloaded": false }, … ] }`.
- **Errors:** 401; 403; 404.
- **Example:** `curl http://localhost:3000/api/tickets/19/suggestions -H "Authorization: Bearer $TOKEN"`

### 12. POST /tickets/{id}/assign

- **Purpose:** first assignment: `MOI` → `DA_PHAN_CONG`, and one `PHAN_CONG` row in the history.
- **Access:** manager.
- **Request body:** `{ "technicianId": 3 }`.
- **Success 200:** `{ "ticket": <ticket>, "log": <log>, "warnings": [] }`. `warnings` holds `{ "code": "TECH_OVERLOADED", "message": "…" }` when the technician now has 10 or more open tickets (the assignment still succeeds).
- **Errors:** 400 (no `technicianId`); 401; 403; 404; 409 `TICKET_ALREADY_ASSIGNED`; 422 `TECH_OTHER_CENTER` / `TECH_INVALID`.
- **Example:** `curl -X POST http://localhost:3000/api/tickets/19/assign -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"technicianId":3}'`

### 13. POST /tickets/{id}/reassign

- **Purpose:** hand an assigned ticket to another technician; the history keeps old and new technician and the reason.
- **Access:** manager.
- **Request body:** `{ "technicianId": 2, "reason": "Previous technician is on leave", "confirm": true }`. `reason` is required (≤ 255); `confirm: true` is required when the ticket is `DANG_XU_LY`.
- **Success 200:** `{ "ticket", "log" (action `DOI_KTV`), "warnings": [] }`.
- **Errors:** 400 (no reason); 401; 403; 404; 409 `TICKET_NOT_ASSIGNED`, `ALREADY_ASSIGNED`, `CONFIRM_REQUIRED`, `TICKET_CLOSED`, `APPOINTMENT_OVERLAP`; 422 `TECH_OTHER_CENTER` / `TECH_INVALID`.
- **Example:** `curl -X POST http://localhost:3000/api/tickets/19/reassign -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"technicianId":2,"reason":"On leave"}'`

### 14. GET /tickets/{id}/history

- **Purpose:** the audit trail of a ticket, oldest change first.
- **Access:** manager.
- **Request:** path `id`.
- **Success 200:** `{ "data": [ <log>, … ] }`.
- **Errors:** 401; 403; 404.
- **Example:** `curl http://localhost:3000/api/tickets/19/history -H "Authorization: Bearer $TOKEN"`

### 15. POST /tickets/{id}/status

- **Purpose:** move the ticket one step: `DA_PHAN_CONG` → `DANG_XU_LY` → `HOAN_TAT`. Writes a `DOI_TRANG_THAI` log row.
- **Access:** manager; a technician only on his own ticket.
- **Request body:** `{ "status": "DANG_XU_LY" }`.
- **Success 200:** `{ "ticket": <ticket>, "log": <log> }`.
- **Errors:** 400 (unknown status); 401; 403 (not his ticket); 404; 409 `STATUS_SKIP` ("Phải chuyển qua Đang xử lý trước") or `INVALID_TRANSITION`.
- **Example:** `curl -X POST http://localhost:3000/api/tickets/19/status -H "Authorization: Bearer $KTV_TOKEN" -H "Content-Type: application/json" -d '{"status":"DANG_XU_LY"}'`

### 16. GET /tickets/{id}/appointments

- **Purpose:** booked appointments of a ticket.
- **Access:** manager.
- **Request:** path `id`.
- **Success 200:** `{ "data": [ { "appointment_id": 9, "appointment_type": "GIAO", "start_time": "…", "end_time": "…" } ] }`. Cancelled appointments are not listed.
- **Errors:** 401; 403; 404.
- **Example:** `curl http://localhost:3000/api/tickets/19/appointments -H "Authorization: Bearer $TOKEN"`

### 17. POST /tickets/{id}/appointments

- **Purpose:** book a hand-over or pick-up time with the ticket's technician (QT-05).
- **Access:** manager.
- **Request body:** `{ "type": "GIAO", "startTime": "2027-02-26T02:00:00Z", "endTime": "2027-02-26T03:00:00Z" }`; `endTime` must be after `startTime`.
- **Success 201:** `{ "data": <appointment> }`.
- **Errors:** 400; 401; 403; 404; 409 `APPOINTMENT_OVERLAP`, `TICKET_NOT_ASSIGNED`, `TICKET_CLOSED`.
- **Example:** `curl -X POST http://localhost:3000/api/tickets/19/appointments -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"type":"GIAO","startTime":"2027-02-26T02:00:00Z","endTime":"2027-02-26T03:00:00Z"}'`

### 18. GET /appointments/{id}

- **Purpose:** one appointment, including a cancelled one (`status` shows `DA_HUY`).
- **Access:** manager.
- **Request:** path `id`.
- **Success 200:** `{ "data": <appointment> }`.
- **Errors:** 400; 401; 403; 404.
- **Example:** `curl http://localhost:3000/api/appointments/9 -H "Authorization: Bearer $TOKEN"`

### 19. PUT /appointments/{id}

- **Purpose:** change type or time of a booked appointment. The overlap check ignores the appointment being edited, so moving it one hour later works.
- **Access:** manager.
- **Request body:** `{ "type": "GIAO", "startTime": "…", "endTime": "…" }`.
- **Success 200:** `{ "data": <appointment> }`.
- **Errors:** 400; 401; 403; 404; 409 `APPOINTMENT_CANCELLED`, `TICKET_CLOSED`, `APPOINTMENT_OVERLAP`.
- **Example:** `curl -X PUT http://localhost:3000/api/appointments/9 -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"type":"GIAO","startTime":"2027-02-26T03:00:00Z","endTime":"2027-02-26T04:00:00Z"}'`

### 20. DELETE /appointments/{id}

- **Purpose:** cancel an appointment. It is a soft delete: the row stays with `status = DA_HUY` and the time slot becomes free again.
- **Access:** manager.
- **Request:** path `id`.
- **Success 204:** empty body.
- **Errors:** 400; 401; 403; 404; 409 `APPOINTMENT_CANCELLED` (already cancelled).
- **Example:** `curl -X DELETE http://localhost:3000/api/appointments/9 -H "Authorization: Bearer $TOKEN"`

## 5. Quick start with curl

```bash
TOKEN=$(curl -s -X POST http://localhost:3000/api/auth/login -H "Content-Type: application/json" \
  -d '{"username":"dieu.phoi","password":"demo123"}' | sed -E 's/.*"token":"([^"]+)".*/\1/')
curl -s http://localhost:3000/api/tickets?status=MOI -H "Authorization: Bearer $TOKEN"
```

Not implemented in v1.0: sending SMS or e-mail appointment notices to the customer (requirement FR07), see the README.
